# DroidDeck + Mavk — экспериментальный форк для Mali

**Steam и Windows-игры на обычном Galaxy Tab S11 / Mali-G925 с
экспериментальной Vulkan-прослойкой и выводом через AHardwareBuffer.**

[English](README.md) · [Скачать тестовый APK](https://github.com/dt0-imsyu/DroidDeck/releases) · [Установка и запуск](docs/TRY_TEST_APK.md) · [Обзор для разработчиков](docs/MAVK_DEVELOPER_REVIEW.md) · [Исходный DroidDeck](https://github.com/Droid-Deck/DroidDeck)

Это независимый экспериментальный форк **dt0-imsyu**, а не официальный релиз
DroidDeck. Сохранены интерфейс DroidDeck, Steam, ARM64 Proton/Wine/FEX и
исходный поддерживаемый путь Adreno/Turnip. Root, разблокировка загрузчика,
прошивка или изменение SELinux не нужны. Основная проверенная конфигурация —
stock Android 16 на Tab S11; эти проверки не доказывают поддержку других GPU.

## Установить и попробовать — без команд для каждой игры

1. Скачай **DroidDeck-Mavk-demo.apk** из **Releases** этого форка и установи
   через Android. Пакет `.mavk` установлен отдельно от оригинального приложения.
2. Пройди обычную установку Linux/runtime в DroidDeck. Steam загрузится при
   первом запуске. На Android 14+ включи **Disable child process restrictions**
   в параметрах разработчика — это требование исходного DroidDeck.
3. До старта сессии открой настройки launcher → Device и включи
   **Mavk / Mali — experimental** и **Mavk AHB display (experimental)**.
   **Hardware Steam interface** необязателен. Перезапусти DroidDeck, если попросит.
4. Выбери **1920×1080** до запуска Steam; для этого fullscreen SDR-пути оставь
   HDR выключенным. Войди в свою учётную запись Steam и установи имеющуюся игру.
5. Нажми обычную **Play** в Steam или библиотеке DroidDeck. Mavk, проверенный
   Sarek и политика запуска уже внутри APK. Для проверенного пути не нужны
   копирование библиотек, сборка исходников, терминал или команды на каждую игру.

Для демонстрации HL2 используй низкую графику со средними объектами/текстурами.
Не меняй разрешение внутри HL2: останови сессию перед выбором другого режима.
В начале первой главы возможен чёрный переход до появления сцены. При проблемах
с выводом выключи AHB и перезапусти приложение для использования X11/SHM.

[Подробный быстрый старт и fallback](docs/TRY_TEST_APK.md). Явный выбор Steam
compatibility tool сохраняется: убери старое принудительное native/другое
переопределение, если нужен автоматический Windows/Proton для dual-platform игры.

[Видео геймплея](https://drive.google.com/drive/folders/14fmiUE_v605aGOI5DPf705XoJdSCv_rI?usp=sharing).

## Что действительно работает

| Сценарий | Доказательство на Tab S11 / Mali-G925 |
| --- | --- |
| HL2, Full HD, низкая графика + средние объекты/текстуры | По наблюдению владельца: от 30 FPS, местами стабильные 60 |
| HL2, почти максимальная графика | Обычно 20–30 FPS по наблюдению владельца; зависит от сцены |
| Muck | Рабочий рендер; примерно 12–13 отображённых buffers/с в одной тяжёлой сцене, 9.1 в другой |
| Движущееся меню Muck | Около 34–35 отображённых buffers/с, AHB без CPU-копирования framebuffer |
| Обычный запуск из пакета | Проверены меню/первая сцена в поезде HL2 и меню Muck; владелец повторно проверил обе кнопки Play |
| AHB / SHM | Проверены счётчики AHB/копирований, движущийся D3D11 SHM fallback и кадр загрузки игры |
| Resize/input | Отдельный D3D11 ResizeBuffers-тест прошёл; масштабирование абсолютного указателя исправлено |

FPS HL2 — наблюдения владельца, а не контролируемый бенчмарк или постоянные 60 FPS.
Вызовы Present, отображённые Android-буферы и уникальные игровые кадры — разные
метрики. Результат зависит от сцены, настроек и нагрева; меню/загрузка не равны геймплею.

Известные ограничения: низкий FPS в мире Muck; отдельные чёрные/диагональные
артефакты; редкие подвисания персонажей/звука HL2; нестабильная смена разрешения
внутри HL2; некоторые live-alias случаи D3D9; отсутствие PE32 D3D11; startup-блокеры
native Linux/FEX, например DDNet. Полные upstream DXVK/Vulkan conformance и
переносимость AHB на Adreno/другие Mali не заявляются. В Steam-ориентированной
сборке отсутствуют необязательные Rust-движки скачивания сторонних магазинов.

## Архитектура и переиспользование

`Steam → ARM64 Proton/Wine/FEX → экспериментальный DXVK-Sarek → Mavk → libhybris → штатный Android Vulkan/Mali`

XCB/Wayland WSI импортирует Android hardware buffers и использует явные
acquire/release fences. Native RGBA может попадать в Android-слой без
CPU-копирования framebuffer; BGRA требует GPU blit. SHM остаётся рабочим
резервным вариантом. Вывод можно изучать отдельно от shader-совместимости Mavk
и переносить на другие GPU, но такой перенос ещё требует аппаратной проверки.

* Этот репозиторий: launcher/session lifecycle, Android compositor, ввод,
  обычная политика запуска игр и выбор экспериментального backend.
* [Mavk](https://github.com/dt0-imsyu/Mavk): общее Core/Compatibility, Vulkan-адаптер
  и WSI-исходники. Доступ контролирует владелец; до отдельного открытия репозиторий
  может оставаться приватным.
* [Обзор для разработчиков](docs/MAVK_DEVELOPER_REVIEW.md): исходные точки входа,
  владение буферами/fences, воспроизведение и ограничения.

Исходный Adreno/DXVK-путь по-прежнему можно выбрать. Sarek — экспериментальный
потребитель для Mali, а не обязательная замена для всех устройств. Сам Mavk
не предоставляет WDDM или аппаратное ускорение Windows DWM в U-AVF.

## Сборка исходников и отладка

**Для проверки игр используй APK.** Для сборки есть [README.MAVK.md](README.MAVK.md)
и [инструкция с pinned inputs](docs/PINNED_REVIEW_BUILD.md). Обычная Gradle-сборка
приложения/native compositor проверена из чистой копии с внешними зависимостями,
сверенными по хешам. Это не полная пересборка всех сторонних компонентов из исходников.
Исходный полный путь — `tools/build_local.sh` с описанными Docker/JDK/Android
SDK/NDK/Rust/Python/zstd инструментами. Необязательные магазины можно исключить.

Для сообщения об ошибке используй **Share logs** из Setup/шторки сессии. Укажи
устройство/GPU, версию APK, игру, разрешение/настройки и AHB/SHM, приложи короткую
движущуюся сцену. Убери личные данные. [Build checkpoint](docs/BUILD_CHECKPOINT_2026-10-26.md)
содержит успешные профильные проверки и непройденную часть общего Windows-host
JVM-набора. Успешная игра из пакета не означает проверку всех функций upstream.

## Авторы и лицензии

DroidDeck остаётся под **GPLv3**, см. [LICENSE](LICENSE). Исходные runtime, ввод
и контроллеры опираются на DroidDeck, WinNative и Bannerlator/maxjivi05. Магазины
также используют работы Legendary/gogdl и их авторов; Steam/Proton принадлежат
Valve. Форк не связан с Valve и не является одобренным upstream-релизом.

Оригинальная работа Mavk — dt0-imsyu и участников под Apache 2.0, кроме явно
отмеченных сторонних/производных компонентов. WSI — MIT, производный Proton
wrapper остаётся GPLv3. Sarek, Mesa, libhybris, Openbox и компиляторные зависимости
сохраняют исходные лицензии/уведомления. Пробелы source coverage записаны;
экспериментальный статус APK не меняет лицензионные условия.
